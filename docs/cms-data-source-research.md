# 四模块数据源与自动化接入调研

日期：2026年10月13日。范围：能力测评、评分与榜单、价格对比、使用技巧与教程；沿用已选 Halo。本文给出接入与存储建议，功能开发和服务器配置保持当前状态。

## 推荐组合

**测评与教程用 Markdown 编写，评分与价格用 JSON 交换；Halo 管理草稿、审核和发布，前台读取已发布内容与缓存。** 自动化先解决收集、清洗、去重和生成草稿，随后按来源与字段逐步开放自动更新。

用户随后明确：自动化生产入口是 Codex skills，四模块都交付统一稿件包；Halo 插件只有一个包接收入口，不建设链接/Markdown/Word 三种生成界面。首版均人工审核发布，图片附件计划采用对象存储，公开内容接 CDN。最新交付与管理约定见[统一稿件包流程](./content-package-workflow.md)。

“数据源”需要分成两件事：外部内容从哪里来，以及进入本站后以什么格式保存。外部源可能是 API、网页、Git 仓库或视频；这些都可以转换成本站统一的 Markdown 或 JSON，不必让每个页面直接访问外部网站。

| 模块 | 优先上游来源 | 进入本站的格式 | 适合自动化的部分 |
|---|---|---|---|
| 能力测评 | 精选作者的原始测评、官方文档与发布说明，本站补充核验 | Markdown 正文＋结构化来源、工具、任务和媒体信息 | 发现素材、去重、提取出处、生成带引用的摘要草稿 |
| 评分与榜单 | 原始评测机构、可授权的数据 API、具体开放评测数据集 | JSON 评分记录＋榜单规则；说明文字可用 Markdown | 定期获取成绩、匹配型号、保存历史、按同一口径重排 |
| 价格对比 | 官方订阅及额度页面优先；官方 API 价目表、OpenRouter 补充 | JSON 套餐、报价、限制和实测记录 | 价格变更监测、固定字段提取、对比和过期提醒 |
| 使用技巧与教程 | 官方帮助中心、明确许可的仓库与作者内容，本站复现 | Markdown 步骤＋工具版本、提示词、附件和验证日期 | 获取更新、整理步骤草稿、识别过期版本与失效链接 |

这符合商业计划书面向办公用户与 AI 新手的定位。榜单仍以聚合为主，本站只补充少量任务核验；价格重点是会员值不值、免费额度能做什么，避免首版变成主要服务开发者的 API 价目表。

## 能力测评的数据源

### 来源选择

| 候选 | 用途与接入方式 | 首期处理 |
|---|---|---|
| [Keygate 测评](https://keygate.ai/insights) | 页面有选型文章、对比和出处线索；作为候选测评目录 | 收集链接、作者、日期和自己的摘要；批量正文导入需确认许可及稳定接口 |
| [降噪](https://aihuangshu.com/) | 精选访谈与长文，并链接原始视频 | 用来发现原作者和视频；尽量回溯原始出处，避免再次聚合丢失上下文 |
| 官方产品帮助中心、发布说明、模型卡 | 核对产品功能、版本与限制；由公开 API、仓库或允许获取的页面接入 | 官方宣传与独立实测分别标记，不把功能介绍自动改成测评结论 |
| 明确允许使用的作者稿件与本站原稿 | 文件交付、私有仓库或后台导入 | 作为 Markdown 自动导入的首个样本，连同素材清单与来源一起接入 |
| [arXiv API](https://info.arxiv.org/help/api/tou.html) | 研究线索、论文元数据与链接 | 仅作素材发现；API 元数据的许可不等于论文全文的许可 |

Keygate 与降噪的页面可以访问，但此次没有确认可直接用于批量商业转载的接口与授权。它们适合作为选题入口，不能据此把整站正文复制进本站。导流链接、翻译和 AI 改写本身都不应作为“已获授权”的记录。

### Markdown 应保存什么

稿件包包含正文 `.md`、JSON 元数据/业务数据和附件引用清单。作者的文章头部元数据由生产侧提取到统一 JSON，避免重复维护。元数据至少包括稳定 ID、标题、摘要、任务分类、工具及版本、原作者、原文 URL、原文日期、采集日期、内容类型和使用范围。内容类型区分原创实测、外部摘要、官方资料说明。

摘要中的重要结论应关联出处或证据。自动化可以整理证据，但不能把“某作者认为”改成“本站测试证明”，也不能凭生成的文字补造耗时、分数和试用结果。

**Markdown 导入需要明确的渲染环节。** Halo 2.26.1 的内容更新参数分别包含原文 `raw`、渲染内容 `content` 和格式 `rawType`；仅填写 `rawType=markdown` 不能作为“上传文件后自动渲染已经成立”的依据。Codex skills 提取输入文档与元数据，插件接收标准包、渲染 Markdown 并清理 HTML，保存为完整草稿。[Halo 2.26.1 内容参数源码](https://github.com/halo-dev/halo/blob/v2.26.1/application/src/main/java/run/halo/app/content/ContentUpdateParam.java)

视频保存平台、视频 ID、链接、说明及封面信息，再由组件生成允许的播放器。YouTube 有官方 iframe 播放器接口；实际嵌入效果仍需在目标用户网络下验证。普通 Markdown 视频链接不会自动成为播放器。[YouTube 嵌入接口](https://developers.google.com/youtube/iframe_api_reference)

Markdown 便于版本管理和迁移，但它只保存文字及引用。自己的图片、视频和结果文件要另做附件备份；第三方嵌入视频应保留来源链接和失效降级展示，不将自动下载视频作为默认流程。

### 用 JSON 保存成绩，用规则生成排名

每条评分记录保存工具、型号、评测机构、评测项目、项目版本、任务类别、运行配置、原始成绩、单位、分数方向、日期、出处和原始数据版本。样本量、置信区间等字段仅在来源提供时保存，未知保持未知。

工具产品与底层模型分别建 ID，例如一个会员产品不等于某个固定模型版本。名称相似不能自动合并；匹配不确定时进入待确认列表。否则价格、评分和教程会关联到错误对象。

榜单是规则计算出的展示结果，不以 Markdown 表格中的名次作为唯一数据。每个榜单记录所用评分集、筛选条件、排序方法、版本及更新时间。不同基准的百分比、Elo 和综合指数分别展示；要做本站推荐顺序，则另给权重、证据和推荐理由，不能直接平均原始分数。

Markdown 可以解释评分方法，但不适合作为成绩的唯一结构化来源。JavaScript 适合页面代码，不适合作为自动接入的数据文件；使用 JSON，避免执行来源提供的代码。CSV 可以作为人工批量导入格式，进入系统后统一校验为相同记录结构。

### 价格记录的最小字段

保存产品与套餐 ID、产品版本、地区、渠道、币种、标价、收费周期、实际扣款周期、年付总额、适用条件、免费额度、额度单位、刷新规则、功能限制、出处、观察与核验时间。价格用十进制数值处理；JSON 交换时可用十进制字符串，避免浮点计算误差。

实际性价比单独保存为任务实测：任务与输入样本、工具版本、套餐、结果是否达标、耗时、额度变化或 token 用量、重复次数及日期。自动化只能填写可观测字段，不能从套餐说明推算真实体验；订阅额度消耗也不能直接当成 API 费用。换汇后的参考价格另记汇率来源和日期，原币报价始终保留。

同一产品在不同地区、渠道、周期或新旧用户条件下的报价并存。一次抓取失败保留上次已核验结果，并显示更新时间；只对超过设定有效期的记录标注待复核，不清空价格或显示免费。

## 使用技巧与教程的数据源

优先收集官方操作文档、工具发布说明、明确许可的 Git 仓库示例和得到作者允许的教程。Kimi 的[官方帮助中心](https://www.kimi.com/help)可作为办公任务教程的起始素材；后续按 PPT、表格、文档、编程等任务扩充来源。

仓库可通过 [GitHub Contents API](https://docs.github.com/en/rest/repos/contents)读取文件和版本信息。来源清单保存仓库、具体文件路径、commit、作者及许可；仓库开放访问不意味着所有文件都采用相同许可。`SKILL.md` 可作为素材文件接入，但读取内容不等于授权执行其命令，应先转为可检查的步骤与草稿。

教程正文使用 Markdown，结构化字段保存适用工具与版本、前置条件、操作步骤、可复制提示词、样例输出、附件、常见失败、最后复现时间和对应来源。官方文档更新或工具版本变化后生成复核任务；涉及界面操作和真实结果的教程由人复现后发布。

优先自动获取作者提供的 Markdown、公开文件 API 或正式 Feed。HTML 页面需要单独提取器，视频需要明确可取得且可使用的字幕或作者稿件；不要把所有来源都当成天然 Markdown。上游全文不可保存时，只保留允许使用的元数据、链接和本站摘要。

## 保存方式与前台性能

### 三层保存

| 层 | 保存内容 | 推荐方式 |
|---|---|---|
| 来源与导入 | 允许保留的原始响应、Markdown、来源版本、内容哈希、附件清单 | 私有文件目录或仓库；按来源与日期归档，不进入公开静态目录 |
| 编辑与发布管理 | 稿件与结构化记录、审核状态、修订、来源关系和发布快照 | 沿用 Halo 的存储与现有 PostgreSQL，由插件/API 写入；首期不另加业务数据库 |
| 公众读取 | 已发布 HTML、公开 JSON、筛选索引及对比所需字段 | 页面缓存；数据量适小时生成带版本的公开 JSON，后续按实测决定分页 API |

Markdown 和 JSON 是输入、迁移及导出的格式，后台数据库负责编辑状态。某条记录必须明确唯一写入方：后台可编辑时，导出文件是备份或派生结果；由文件管理时，后台只导入与审核修改建议。不能长期让同一篇文章在 Git 和后台各自自由修改再互相覆盖。

### 价格与榜单可以只用文件吗

**可以。** 记录数量小、只有一个写入流程、运营愿意编辑文件、更新时能整批校验和切换版本，JSON 足以承载价格或榜单展示。两个版本并存并由发布清单切换，可保持上一版可读；历史、审核和冲突处理则需要由文件流程自己实现。

当前需要后台结构化录入、草稿隔离、筛选对比及后续自动接入，建议继续用现有 Halo 存储管理这些状态，发布 JSON 作为公开读缓存。这样不增加数据库种类，也不必让每次浏览都查库。若以后明确某模块只由文件自动生成，可将其改成文件管理，但不要同时保留两套可写主数据。

“只是展示、不用业务事务”不足以证明文件比数据库快。前台延迟还受网络往返、缓存命中、渲染、数据包大小和媒体影响。优化目标应是减少公开请求与重复计算，再用相同数据量实测两种读取方式，不先承诺性能提升。

高延迟主机适合服务端输出主要内容，将必要筛选信息合并返回。少量榜单可在浏览器本地筛选、对比；数据增大后分页或分任务加载，避免首次下载全部历史。缓存键包含发布版本，正文、标题、价格和筛选数据必须属于同一版；草稿预览不进入共享缓存。

当前 PoC 已发现原生标题保存会立即改变公开标题。新流程必须把标题、摘要、分类、关联、正文及结构化字段一起保存在待发布版本；公众读取完整已发布快照。自动导入不能直接修改已发布文章的原生标题。这一隔离尚待实现，不能用“正文支持草稿”代替完整验收。

备份需要数据库、Markdown/JSON 导出、附件与配置。Git 管理文字版本很方便，大型媒体另存储；只备份 `.md` 或公开 JSON 无法恢复后台审核状态与全部素材。

## 自动化接入流程

建议流程为：**定期获取或接收文件 → 归档允许保存的原始材料 → 解析成统一记录 → 校验与去重 → 生成差异草稿 → 审核 → 发布完整版本 → 更新公开缓存。** 浏览页面时使用本站已发布数据，外部来源故障不应阻塞访客。

Codex skills 侧为每个来源建立配置：来源 ID、入口地址、接口/文件/网页类型、认证方式、使用范围、更新时间、字段映射和抓取失败规则。Halo 侧仅维护包接收、修订冲突和审核发布规则；首期不必为采集在网站内引入消息队列、搜索集群或新数据库。

| 问题 | 处理要求 |
|---|---|
| 重复抓取 | 使用来源 ID、外部记录 ID、版本或内容哈希识别；同一输入重跑不重复创建 |
| 后台人工修订被覆盖 | 仅更新来源负责的字段，人工摘要、推荐理由等保留；同字段冲突生成待确认差异 |
| 页面改版或字段消失 | 校验必需字段与记录数；异常批次停止发布，不将缺字段覆盖成空值 |
| 不同源相互矛盾 | 保存各自的观测与条件，确定核验来源后再展示；不以最新采集时间替代可信度 |
| 请求限额与临时故障 | 遵守来源规则，限制并发，按错误退避重试，支持条件请求和增量抓取 |
| 导入内容携带代码 | Markdown 渲染清理脚本与危险 URL；媒体用允许的平台组件，不执行外部 JS 或教程命令 |
| 自动化权限过大 | 采集账号仅创建或更新草稿；编辑、发布及配置权限分别授予，密钥不进公开包 |
| 发布部分失败 | 先生成并验证完整版本，再切换公开版本；失败保留上一版并可回滚 |

生产侧初始频率可设为：素材与教程每日发现、会员价格每日检查变化、评分按机构更新周期获取。都是运营建议，需按接口限制和维护价值调整；没有来源更新时不必重复渲染全部内容。首版全部入草稿，人工审核发布。未来是否开放固定字段自动发布需另定规则，不属于本版已确认范围。

当前测试环境的容器公网出站尚未验证。采集可先在开发机或独立任务进程完成，向 Halo 提交草稿；后台任务异步运行，不放在访客请求内。若迁移到服务器容器，再单独验证网络、权限和资源限额，不为了采集擅自改变主机转发设置。

## 首批接入与 PoC 验证顺序

按对普通用户的价值和实现成本，先做三条小流程：会员价格变更草稿、作者提供的 Markdown 导入、一个授权明确的评分 JSON 导入。OpenRouter 作为接口采集与单位转换的辅助样本；Artificial Analysis 待公开展示授权与费用明确后再决定，不以付费接入阻塞功能验证。

| 顺序 | 输入与范围 | 验收条件 | 对应已有 PoC |
|---|---|---|---|
| 1 | 一份测评、一份教程 Markdown，包含标题、表格、图片、视频及提示词 | 自动生成可预览草稿；修改标题等字段公众仍读旧版；发布后整版切换；导出后可重新导入 | P1、P2、P3、P6 |
| 2 | Kimi 官方会员页面样本＋人工核验记录；另加两种工具的结构化套餐样本 | 月付、年付、地区、额度条件可筛选和比较；页面变化只产生差异草稿；解析异常保留旧价 | P2、P3、P4 |
| 3 | 一个许可明确的评分文件；模拟不同版本、同名模型和不同基准 | 不混合口径；重跑无重复；型号不确定待确认；榜单可追溯来源与计算规则 | P2、P3、P4 |
| 4 | 两条 OpenRouter 分页模型记录与单位转换用例 | 正确记录渠道、单位和来源时间；缺失值与零值不同；失败和限流可重试，不调用付费推理 | P4 |
| 5 | 已发布 JSON、HTML、草稿和后台修改 | 公开文件及缓存不泄露草稿；回滚一致；匿名无写权限；有限缓存更新而非长期旧数据 | P1、P6 |
| 6 | 相同数据集的直接读取与缓存读取，加服务器现有服务监控 | 记录首屏、响应时间、资源占用和数据包大小；低强度测试不挤占已有服务；从备份恢复可核验 | P7、P8 |

上述是下一轮验证计划。此次完成来源调研与一次只读接口检查，未部署采集器、未购买数据授权、未实现业务插件；现有 P1 至 P8 的未完成项继续保留在[进度记录](./cms-poc-progress.md)中。
