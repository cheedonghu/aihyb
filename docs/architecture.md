# 网站架构

本页描述当前源码职责。术语以 [CONTEXT.md](../CONTEXT.md) 为准，稿件结构以 [Schema](../contracts/content-package-v1.schema.json) 为准。

## 组件与数据

网站采用 Halo 2.26、PostgreSQL、Thymeleaf 主题及自有 `plugin-aihyb` 插件。插件后端使用 Java 21，控制台扩展使用 Vue 3；没有另建独立公众前端或修改 Halo 内核。

- `plugin-aihyb/src/main/java`：稿件接收、审核、发布版本保护、公开查询、正文渲染、媒体、任务标签与站点配置。
- `plugin-aihyb/ui/src`：原生文章编辑扩展、稿件结构化字段、审核界面和站点配置。API 客户端由 OpenAPI 生成并随源码保存。
- `plugin-aihyb/src/main/resources/theme-assets`：插件提供的页面样式、交互脚本及运行时品牌图片。
- `themes/shared`：主题定制源文件；`themes/adapters`：部署用模板及哈希清单；`themes/upstream`：生成适配所需的固定上游版本及许可。

Halo 通过官方资源客户端将内容、不可变修订及发布状态存入 PostgreSQL。受管理的原生文章承载当前草稿、批准和公开修订；公开列表、正文和 DTO 读取相同的发布版本。保存草稿不改变已经发布的标题、正文、结构化数据及栏目；批准只适用于明确修订，修改后必须重新审核。

插件是 Halo 原生文章、分类、标签、附件、主题和权限能力的补充，不另建一套发布体系；代码上独立构建和部署，但内容模型仍以 Halo 原生资源为载体。原生文章是快讯和普通文章的默认路径，稿件包只在需要审核、结构化数据或私有媒体时启用。定位与媒体存储分层见 [ADR 0002](adr/0002-plugin-supplement-and-media-storage.md)。

真实稿件和附件是运营数据，保存在 Halo、数据库与 COS，并通过独立备份保护。仓库只保存协议与虚构测试材料。内容制作、视频生产及来源资料归档均在仓库外进行。

## 页面与编辑规则

首页包含能力测评、评分与榜单、价格对比、使用技巧与教程四个入口。「最新资讯」自动汇集最新公开发布的文章：首页展示最新五篇，独立列表提供分页。资讯、能力测评、教程以及未归入上述模块的普通文章都会进入汇总，无需额外选择资讯分类；任何公开栏目包含「评分与榜单」或「价格对比」的内容暂时排除，多分类文章只出现一次。汇总卡片保留原栏目和原文链接，按发布时间倒序排列，日期使用北京时间。稿件包的 `content.section=news` 仍控制文章正文栏目及样式，`content.news_date` 保留原收录日期；汇总只在缺少发布时间时用其兼容旧数据。

后台直接编辑的普通文章按原生分类别名 `reviews`、`leaderboards`、`prices`、`tutorials`、`news` 进入对应模块；选择多个模块分类时分别收录。草稿允许暂不选择栏目，原生 HTTP 发布及已发布文章修改时，必须至少关联一个仍存在的上述栏目分类；正文、撤回和回收操作继续由 Halo 原生流程处理。历史没有匹配模块分类的普通文章仍在公开结果中使用 `kind=news`，只进入最新文章汇总。首页和栏目列表共用公开查询，普通文章使用标题、摘要、发布时间、可选封面及原文链接展示，不生成评分、榜单表格、价格方案或核验结论。稿件包继续按发布版本展示结构化信息。公开结果中的 `content.sections` 记录普通文章的栏目，`content.published_at` 用于合并排序，不作为标准稿件输入字段。

文章面包屑采用「首页 → 所属栏目 → 正文」。栏目名称和链接从文章实际保存的分类引用解析，分类列表中第一个有效的站点栏目用于面包屑；多栏目文章仍在全部所选栏目收录。能力测评、评分与榜单、价格对比、使用技巧与教程、最新资讯分别链接到 `/aihyb/review`、`/aihyb/leaderboard`、`/aihyb/pricing`、`/aihyb/tutorial`、`/aihyb/news`；文章标题下的同类分类标签也使用这些入口。进入最新文章汇总不改变文章自身的栏目归属，未归栏旧文的面包屑回退「内容归档」。分类校验在 Halo 原生安全链之后执行，保留原生身份、权限、版本冲突及定时发布处理；它约束原生 HTTP 写入，不替代数据库级约束，也不自动修改历史文章或其他插件的内部写入。

场景和任务标签共用可配置词表，一个任务标签可以归属多个场景。“综合”按具体模型版本人工排序，不从不同测评中自动合成分数。决策依据见[任务分类 ADR](adr/0001-shared-task-taxonomy.md)。

评分与榜单栏目使用本站独立维护的固定榜单组件，ModelDial 只是其中一个数据源。2026-11-09 用户要求取消模型搜索，并将评分改为从上到下排列的水平条形对比图：每行展示原名次、模型名称、宽横条和右侧原始分数，不再提供模型搜索、名称排序或重置栏。横条以 0 为起点、以本榜最大值为刻度上界，长度只表达当前榜单的原始分值；越低越好的指标保留数值与方向，不反算新分数。真实零分的条长为 0，未知值显示“未提供”且不生成横条；人工综合榜保留编辑名次及参考评分，不用条长暗示自动综合成绩。不同快照分别展示，不合并口径、不修改成绩、名次或并列关系。来源、版本、配置、基准和方法均不前置，来源集中为最底部的引用链接及默认折叠的说明，底层记录继续可追溯。桌面将模型名与横条并排，手机将模型名置于横条上方，保留完整数值且不横向滚动。JavaScript 只增强榜单切换及 hash 定位；无 JavaScript 时本页所有快照和解读仍可阅读。

评分与榜单栏目、网站首页的榜单入口和榜单详情复用同一份水平图表组件。局部样式集中在插件资源 [leaderboard.css](../plugin-aihyb/src/main/resources/theme-assets/leaderboard.css)，由栏目模板、原生文章 head 处理器及后台预览共同加载，不把栏目页面的全局重置样式带入原生文章。底部折叠的引用说明继续按名次保留每条依据及其对应来源链接，多个来源不丢失逐项归属。已发布详情通过主题中的运行时桥接按公开修订重渲染，展示更新无需重新导入、审核或发布数据。

ModelDial 作为数据来源接入，不控制本站模板，也不替代能力测评模块。首版提供[离线稿件转换器](modeldial-import.md)：显式读取下载的五维成绩 JSON，按每轴最高分配置生成五份现有格式的榜单草稿及来源元数据，不联网、不直接提交或发布。未知成绩、模型/路由身份与评分版本按来源核对；旧三维接口和来源加权综合成绩不映射为本站综合榜。公开署名、许可及处理说明放入正文，不能只写在后台来源备注。自动采集、定时同步及线上导入尚未启用。

页脚不再重复展示 Logo 与品牌宣传语，只保留五个栏目和内容归档入口；场景及任务标签在栏目页筛选区展示，避免在页脚按栏目重复展开。桌面端导航居中横排，手机端两列排列，继续按站点配置居中展示有效二维码。版权与备案信息由 Earth 主题在导航下方居中同行展示，窄屏空间不足时自然换行；备案号和链接仍只从主题现有备案设置读取。插件独立页脚继续保留版权信息。

正文采用摘要、关键信息、章节导航和来源卡片。测评保留过程及样例；榜单保留成绩与排名依据；价格同时呈现全部方案、权益、限制和同任务用量条件；教程保留准备清单与操作步骤。没有核验的数据不得作为真实排名或价格发布。视觉取舍见[设计参考](design-references.md)。

内容列表的通用标题使用「AI好用指南」。原生文章作者显示 Halo 用户的 `spec.displayName`，可以在个人资料或用户管理中修改，对应用户的历史文章同步更新；登录用户名继续作为身份标识。原生文章设置的高级选项可逐篇选择其他已有用户作为作者。生产历史作者与当前管理员统一署名「AI好用官」。

原生文章默认别名采用 Halo 的 `system.post.slugGenerationStrategy=timestamp`，避免标题自动转拼音形成长串；新建文章仍可手动填写更有含义的别名。设置只影响新建文章，已有文章的别名和链接保持原值；稿件包继续使用稳定的 `aihyb-<content_id>`。

启用后第一次发布且当前公开的文章，插件向 Halo 原生 Counter 增加一次 100–500（含两端）的随机初始基数，真实浏览量继续由 Halo 累加。基数与初始化标记保存在同一个 Counter 版本中，重复发布、并发重试和插件重启不重复增加；派生的文章统计由 Halo 自行同步。首次启用时间持久化保存，早于启用时间已发布的文章不回填，包括当时仅内部或私有可见的文章；首次发布判断依据 Halo 保留的发布条件时间，不受手动回填显示发布日期影响。

## 媒体、发现入口与权限

稿件包附件由 Halo 管理稳定引用，文件位于私有 COS。公开图片经发布版本及权限检查后短期签名跳转，私有预览、视频和下载仍通过受控网关；Markdown 使用 `asset://附件ID`。原生文章附件继续使用 Halo 附件策略，当前为本地公开存储 `/upload/`。服务端限制链接、媒体类型、附件归属及可公开字段。

搜索、Feed 和站点地图必须遵守草稿与公开修订隔离。插件依赖 Feed >=1.5.0，共享事件 API 作为 `compileOnly` 依赖保存了来源与许可。升级相关组件需要重新验证缓存失效、别名及标签路由。

数据库和 Halo 文件共同构成恢复所需数据，单份文章 JSON 不替代站点备份。CDN、定时备份、完整负载验收及可靠缓存失效重试尚未纳入本次仓库整理；历史验证结论位于外部归档，不将其视为本轮重新验证。
