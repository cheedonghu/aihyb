## 1. 目标与边界

PoC（概念验证）是一个小型可运行试验：证明 **Halo 社区版 + 成熟主题 + 自有 Java/Vue 插件** 可以支撑当前四模块，并识别需要额外开发的部分。用户已选 Halo，本轮不默认安装或实现其他候选。

范围为能力测评、评分与榜单、价格对比、使用技巧与教程。只用模拟来源和虚构工具/价格；不采集真实收费 API，不迁移现有数据，不接支付/注册/论坛，不部署生产服务器。两个 UI 主题只用于验证可替换性，不要求同时维护两套正式视觉产品。

内容生产入口按用户最新要求固定在 Codex skills 侧。四模块以统一稿件包提交，Halo 插件只提供一个自动化接收入口与后台审核发布，不建设链接/Markdown/Word 三种生成界面。包格式、对象存储与 CDN 的设计边界见[统一稿件包流程](./content-package-workflow.md)。

用户后续授权安装与开始验证，并将测试服务器改为 `5.231.253.4:22333`。已部署 Docker、Halo 和 PostgreSQL，录入四模块原生内容样例，完成正文草稿/发布/恢复、匿名读写限制、备份及一次重启的初步检查。结构化业务插件、完整权限矩阵、两套主题、恢复演练和负载测试仍未完成。实际证据与限制见 [执行记录](./cms-poc-progress.md)。

## 3. 演示数据集

小样业务集：10 个虚构工具（模型/应用/智能体）、20 个方案（订阅/API、不同单位/币种、未知/免费值）、10 条结构化测评、3 份任务榜单、6 篇测评长文、4 篇教程、20 个小型媒体文件。至少三分之一先保持草稿。来源均为模拟地址，标记为测试数据。

边界样本必须包括：中文长标题、表格、代码高亮、可复制提示词、长限制说明、空榜单、失效引用、无来源、过期核验日期、缺价格、不同币种/单位、相同分数、外部来源相互矛盾。

负载集在小样通过后生成：1,000 个工具、5,000 个方案/测评记录、1,000 篇短文与固定 100MB 媒体样本。这是测试规模，不是预测流量或已确认首年规模；报告分开统计媒体、数据库与备份占用。

## 4. 八项最小 PoC 及验收标准

### P1：文章草稿、预览、发布与再次修改

1. 编辑新文章 A，保存草稿，登录预览。
2. 发布 A，匿名通过页面与 API 读到 A。
3. 修改为 B，仅保存草稿；分别修改正文、标题、分类、摘要和关联测评。
4. 检查所有公开入口、缓存、列表与 SEO 仍显示批准版本；编辑预览能看到 B。
5. 发布 B，公开入口在设定缓存失效时间内更新；恢复旧正文版本并记录范围。

**通过：** 草稿内容没有从公开页面、API、搜索/站点地图或共享缓存泄露；已发布文章不会因保存新草稿而消失；字段隔离范围有逐项记录。发现 Halo metadata 与正文发布时点不同，必须使用明确的字段快照/适配方案验证，不能只测正文即全部判通过。预览、历史恢复、定时发布分别记录原生/插件/未支持，不混称完整审核。

**证据：** A/B 截图、匿名/编辑 HTTP 响应、页面 HTML、各字段版本对照与缓存头。

### P2：自定义类型、CRUD、查询与并发

定义完整稿件草稿/发布资源，并按需要定义 Tool、SubscriptionPlan、ProductReview、LeaderboardSnapshot 的字段或派生读模型。使用 `AbstractExtension`/GVK/Scheme，注册实际筛选索引；明确哪些资源可写、哪些由发布快照派生，不做双主数据。[官方模型能力](https://docs.halo.run/developer-guide/plugin/api-reference/server/extension)

验证新建、查询、分页、更新、删除/归档；输入负数金额、无来源、失效工具 UUID 等返回可定位的 4xx 错误。两名编辑同时基于旧版本更新，确认冲突被拒绝或明确提示，不静默覆盖。

**通过：** 重启后数据保留；索引筛选/排序正确；draftPayload 与 publishedPayload 可独立保留；只有一次显式发布能切换完整公开快照。关联记录仍被使用时不能无提示删除造成公开页错误。

**证据：** schema/索引定义、CRUD 响应、非法数据与并发冲突记录、重启前后计数。

### P3：后台管理与四模块前台

复用 Halo 原生文章列表、编辑、保存、预览及发布入口；增加 Vue3 稿件数据与审核面板，核验来源、结构化记录及明确修订。前台呈现四个模块与完整数据；生成动作在 Codex skills 侧完成。

**通过：** 两位内容负责人各自完成至少一次“审核方案”“更新测评”“发布榜单”“发布教程”，后台审核不要求修改数据库或调用命令。价格页可按方案类型/任务筛选，最多三项并排比较；不同币种与单位不错误混排。榜单显示口径、理由、来源与日期，教程显示步骤和提示词。编辑未提供来源/核验日期时不能发布结构化结论。

审核一条方案、更新一个榜单建议目标各≤5分钟（不含资料搜集）；这是可调整的试用目标，不是 CMS 性能。记录真实操作步骤与卡点，不用开发者自己演示代替运营试用。

### P4：四模块稿件包接收与更新

由 Codex/测试脚本通过同一接收接口提交 review、tutorial、leaderboard、pricing 四种虚构包。输入覆盖格式版本不支持、无来源、非法金额/单位、缺少附件引用、同交付 ID 异内容、过期 base_revision，以及保存中断后重试。返回可定位字段的错误或草稿修订与授权预览信息。

**通过：** 四类包均只入草稿；同包执行三次不重复创建；同 ID 异内容和过期修订明确拒绝；运营改过的标题不被旧包覆盖；新输入不影响旧公开版；中断后重试可对账。公开字段从同一已批准完整版本生成，评分/价格表从 JSON 生成；包内的发布状态不能取得发布权限。支持记录数/请求尺寸上限，异常包不半包发布。

本轮不要求在 Halo 内运行定时采集、Word 转换或 AI 生成。若启用定时发布，单独验证重启跨过到期时刻的处理；它不等于采集调度。未来 skills 以同一包 Schema 与回执契约接入。

### P5：安装并切换两套 UI 主题

先主题 A，再主题 B，再切回 A。为两套主题分别登记配置、导航、插件布局契约与适配代码。[Halo 主题/插件契约](https://docs.halo.run/developer-guide/plugin/theme-integration)

**通过：** 文章、教程、工具、方案、测评、榜单记录计数与 UUID 不变；四个模块均可访问；至少存在插件默认页面保底。首页导航、手机表格、来源卡片、代码高亮、图片、分页、canonical 和页面标题正常，无缺失模板或 500。主题只改外观，不要求数据搬迁。

手机以 390px、桌面以 1440px 检查；宽比较表可以横向滚动，但页面整体不溢出。记录适配工时；“切换后数据还在、业务页面消失”不算通过，“存在 fallback 但无模块入口”也不算通过。

### P6：API 与权限负向测试

分别用匿名、编辑、发布负责人、管理员和导入机器人调用资源 CRUD、公开接口、预览、导出和发布。测试直接资源 ID、分页/筛选参数、未发布关联、媒体直链与浏览器脚本中的凭据。

**通过：** 匿名只能读已发布 DTO，不能读取资源内 draftPayload、预览或修改数据；编辑不能升权/发管理员操作；导入机器人只能写草稿，不能发布。未授权请求返回 401/403/404 等明确拒绝结果，数据不改变。公开 `api.<group>` 不是免鉴权万能通道，匿名权限只开放专门只读接口。[API 权限规则](https://docs.halo.run/developer-guide/plugin/security/role-template)

默认附件上传是否公开单独记录。需私密的草稿附件必须在受鉴权路径暂存并测试直接 URL；若允许普通媒体先公开，须形成显式产品约定，不能将其计作私密附件验证通过。

**证据：** 角色×操作矩阵、所有失败请求及写前写后比对、打包文件凭据检查结果。

### P7：Compose、重启、备份恢复、迁移与升级

1. 从新目录按 README 一次启动，自动或清楚地完成初始化、装插件和导入样例；如初始化仍需人工点击如实列出。
2. 重启应用/数据库，重建应用容器，校验卷、草稿、已发布数据与附件。
3. 冻结写入后备份数据库、媒体、插件持久数据与版本清单；在独立空库/空目录恢复。
4. 导出中立数据包，在空 PoC 实例经官方 API 导入，校验 UUID、slug、关系、草稿/公开版本及媒体清单。
5. 用仍受支持的前一稳定补丁到目标补丁验证核心升级；另用插件 schema v1→v2 演练新增字段和幂等迁移。若没有安全合适的核心升级路径，记录未执行原因，不能用插件升级冒充核心升级。
6. 在副本上模拟升级失败，按版本与备份恢复；数据库发生不兼容变化时不直接用旧镜像硬降级。

**通过：** 无生产环境依赖；数据计数、引用、关键字段和附件校验和一致；恢复后同权限访问同内容，旧公开版本与新草稿均存在；导入重复执行不会重复记录。RPO 设计≤24小时，恢复建议目标≤60分钟；记录实际耗时及停写窗口。

中立导出至少包含 manifest、四类业务记录、文章/分类、媒体校验和与映射、来源及发布版本；附一个不依赖 Halo 的解析检查，证明数据可读，不把“同 CMS 恢复”单独当成跨 CMS 可替换性证明。其他 CMS 的真实 UI/权限迁移仍不属于本次已验证范围。

### P8：CPU、内存、存储、冷启动与基本响应

在用户新指定的 2C6G Debian 服务器、相同版本、数据和负载下测，分别报告基础内容站与装业务插件后的完整站点。不能把 JVM `-Xmx` 当整机 RSS，不把空库启动当业务负载。

| 场景 | 测量方法 | 建议通过目标（PoC 工程目标） |
|---|---|---|
| 空闲与运营 | 预热后空闲 10 分钟；两名编辑连续操作 15 分钟 | 无重启/OOM；CPU/RSS 无持续异常增长，记录数值而非“正常”两字 |
| 公开查询 | 20 并发，混合四模块页面及基础筛选，持续 10 分钟，三轮 | 业务请求错误率<1%；API p95≤500ms，HTML p95≤1秒；主机 CPU 平均<70% |
| 总内存 | 主机与全部容器同时采样，区分已有服务与 PoC 进程占用 | 指定 2C6G 机器保留≥25%可用内存；其他配置结果单列，不混入本机基线 |
| 重启启动 | 镜像已在本地，从容器启动至 readiness 且页面/API 可访问，三轮 | 每轮≤120秒；无首次镜像下载和构建时间混入 |
| 磁盘 | 前后对比数据库、媒体、插件、日志和备份 | 分项记录 MB、数据条数与每千条增量；不设未经业务确认的容量保证 |
| 编辑稳定性 | 公共负载期间继续保存/预览/发布 | 无丢稿/越权；发布后缓存更新在约定范围内（PoC 建议≤10秒） |

记录机器、磁盘、CPU 限制、JVM 配置、数据库参数、负载脚本、数据集 seed、冷热缓存状态。镜像构建、下载耗时单列；浏览器首屏可另外记录，但本地测试不等于国内公网体验。并发值是测试值，不作为用户规模预测。

若未达目标，先查慢查询/索引、缓存、主题资源和 JVM/DB 配置，限时复测；没有新问题不重复扩展压力测试。指定2C6G机器未通过时明确记录结果；资源升级另行确认，不借原规划假定本机已经满足要求。网络延迟与服务器本地处理时间分开测，不以本地响应代替公网体验。

## 5. 执行顺序、时间与费用

先验证最高风险，以免主题美化完成后才发现数据泄露或无法留草稿：

| 顺序 | 工作包 | 估算工程工时 |
|---|---|---:|
| 1 | 固定版本、确认两套免费主题、Compose 与样例数据 | 3–5小时 |
| 2 | P1 原生文章；P2 自定义资源快照；P6 核心权限 | 8–12小时 |
| 3 | P3 四模块最小后台与前台，不做正式品牌视觉 | 8–14小时 |
