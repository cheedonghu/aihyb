## 高带宽、高延迟的设计要求

新主机的带宽更高是用户提供的条件，未测定实际容量。高带宽可以缩短较大资源的传输；176ms级往返会让多个串行API、脚本和图片依赖累积等待，不能靠带宽消除。

- 四模块首屏由服务端输出主要内容，合并必要数据，避免逐条卡片请求和多个串行接口。
- 静态资源使用压缩、长期浏览器缓存和小包；先加载必要内容，图片按尺寸生成并延迟加载，音视频不首屏自动下载。
- 公开已发布列表和结果使用短时缓存；预览、认证和后台响应不进入共享缓存。
- 运营使用批量编辑/保存减少往返；保存显示状态与失败原因，避免连点重复请求。大陆目标用户的真实首屏与后台操作需另测。
- CDN可降低静态回源和用户距离，但当前未采购、未接入；HTML、API的动态请求延迟仍需分别测。是否采用国内外CDN取决于后续域名、托管与预算。当前入口是纯 HTTP + IP，没有域名与证书，CDN/HTTPS 都要等备案与域名恢复后才能做。

旧服务器6Mbps的容量估算不再作为当前部署限制；图片压缩、缓存和减少请求仍值得保留。公网负载测试需限速、分时，不能为了测量挤占既有服务。
