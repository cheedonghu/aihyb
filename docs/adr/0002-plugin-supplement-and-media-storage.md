# 插件是原生能力的补充，媒体按公开性分层

2026-10-28，用户确认：插件应是 Halo 原生能力的补充，而不是独立的内容体系；“独立”只指代码实现、构建和部署独立。此前为普通文章补图时，确认了原生文章附件与稿件包媒体的差异，一并记录如下。

## 定位

- 内容模型复用 Halo 原生 Post、分类、标签、附件、主题、路由、权限、搜索、Feed 和站点地图；插件不建立与原生文章平行的发布体系。
- 原生文章是快讯和普通文章的默认路径；只有需要审核、结构化数据或私有媒体的内容才使用稿件包。
- 稿件包仍通过受管理的原生 Post 承载路由和主题渲染；Post 注解保存草稿、批准、公开指针，不可变 ContentRevision 保存内容与哈希。原生 Post 是载体，不是第二套数据源。
- 不应仅为使用 COS 而把普通文章改成稿件包；这会把内容流程和存储选择绑在一起。
- 代码实现独立：插件可以单独构建、升级和回滚；这不应演变为产品概念上的独立。

## 媒体存储

- 原生文章图片和封面使用 Halo 附件策略 `default-policy`，文件在服务器本地，公开地址 `/upload/...`，随服务器备份。这是原生文章当前可用的公开路径。
- 稿件包媒体使用 `aihyb-media-private` S3/COS 私有桶，正文以 `asset://` 引用；发布后经 `/apis/api.aihyb.run/v1alpha1/media/{contentId}/file/{revision}/{assetId}` 做修订、公开性和归属校验，再跳转短期签名地址。
- 发布前会检查 S3 对象的匿名 URL 必须返回 401/403；若桶被误设为公共读，发布会被阻止（`MediaService.assertPrivate`）。
- 该网关是“按稿件修订授权媒体”，不是通用 S3 代理。普通文章没有 ContentEntry、ContentRevision、assets 数组和发布修订指针，网关无法解析，因此不能直接使用。
- 私有 COS 直链匿名访问为 403；临时签名 URL 会过期，不适合写入正文长期引用。
- 不把私有桶改为公共读，也不让网关接受任意对象 key；否则会绕过按修订和发布状态的权限检查。

## 如果原生文章需要 COS 公开媒体

需要单独增加公开媒体路由，二选一：

1. 仅对专用前缀开公共读，例如 `aihyb-public/`；桶内其他内容继续保持私有。
2. 增加签名代理或 CDN 回源签名，对外提供稳定 URL。

这属于基础设施或插件功能变更，需要单独确认和安全审查。在此之前，原生文章继续使用本地附件。若未来新增“普通文章媒体网关”，必须保留按文章和附件的授权，不能退化为公开桶代理。

## 后果

- 原生文章配图在本地，不在 COS；与现有原生文章一致，公开可访问且随服务器备份。
- 稿件包媒体保持私有、可审计，但发布链更长、约束更多。
- 原生文章使用 COS 公开媒体需要额外的基础设施或功能开发，不能只改一个附件策略。
- 记录本决定，避免后续把“代码独立”误读为“内容体系独立”，也避免为了复用私有媒体而绕过公开性分层。
