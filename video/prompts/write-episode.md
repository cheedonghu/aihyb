# 写稿规范：把素材写成 episode.json

把本文件和素材清单一起交给 AI（Claude Code、Codex 等），让它产出 `public/episodes/<id>/episode.json`。格式定义见 [README](../README.md#episodejson-格式)。

## 输入

- 选题类型：`资讯` 或 `技巧`。
- 素材清单：目录里每个文件的文件名 + 一句话说明它是什么（例如 `bench.png：官方跑分表，含 HLE、SWE-bench`）。
- 资讯类：原文链接或原文全文；技巧类：要讲的要点、示例、自己踩过的坑。

## 输出要求

1. 只输出合法 JSON，字段严格按 README，不要加未定义字段。
2. 每段 `text` 一到两句、30～60 字，口语化，一段只讲一件事。全片资讯类 4～10 段，技巧类 5～12 段。
3. 第一段直接给结论或最抓人的事实，不要“大家好，今天我们来聊聊”。最后一段一句话收尾，可以引导到 AI 好用榜。
4. 每段的 `visual` 优先用素材清单里的文件；没有合适素材时才用 `title` / `points` / `code` / `quote` 文字卡片，不要编造不存在的文件名。
5. 数字按口播读法写进 `text`（“百分之七十”“二百万亿”），画面卡片里保留原写法（“70%”“200T”）。英文产品名照常写。

## 事实与措辞

- 资讯类只写原文里有的事实。原文没给的数字、日期、对比对象，一律不写，不要“合理推测”。
- 厂商自报的跑分、速度、价格写成“官方称”“官方数据显示”，并在结尾提示有待实测。
- 本站自己没测过的内容，不写“我们实测”“亲测”。
- 不用“碾压”“吊打”“王炸”“封神”之类夸张词，不贬低具体竞品。
- `sources` 必须列出每条事实的出处（标题 + URL）；`credit` 写主要来源，例如“资讯来源：证券时报e公司”。
- 技巧类保留原样的命令、配置、提示词，放进 `code` 卡片；AI 自己补充、没人验证过的步骤，在 `text` 里说明“建议自行验证”。

## 交付前自检

- [ ] `id` 与目录名一致，所有 `src` 文件都在目录里。
- [ ] 每个数字都能在原文或素材里找到。
- [ ] 读一遍全部 `text`，像人说话，没有书面腔和重复。
- [ ] 运行 `python scripts/build.py <id>` 无报错。
